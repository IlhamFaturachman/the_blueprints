## CRITICAL Bugs (3) — Must Fix Before Live Trading

### C1: `direction` Undefined in `evaluate_hybrid_exit` — Stop-Loss Cooldown NEVER Works

| Field | Value |
|-------|-------|
| **File** | `market_discovery_internal/cycles.py:2052` |
| **Severity** | CRITICAL |
| **Discovered** | 23 April 2026 audit |
| **Affects Live** | YES |

**Code:**
```python
# Line 2052
_sl_cooldown_h = EXACT_BRACKET_SL_COOLDOWN_HOURS if direction == "exact" else HYBRID_STOP_LOSS_COOLDOWN_HOURS
```

**Problem:** The variable `direction` is never defined in `evaluate_hybrid_exit()`. The function receives `position` as a dict and extracts `strategy` (line 2004) but never extracts `direction`. This raises `NameError` at runtime.

**Why it's silent:** The entire cooldown block (lines 2043-2056) is wrapped in `try/except Exception` (line 2055), which silently catches the `NameError` and logs a debug message. The `_stop_loss_armed` variable stays `True` (its default from line 2041), meaning **stop losses fire immediately after entry without any cooldown**.

**Impact:**
- The 2-hour cooldown for above/below markets: **BROKEN**
- The 1-hour cooldown for exact-bracket markets: **BROKEN**
- All 3 stop-loss exits on 23 April 2026 were caused by this bug — positions were stopped out by initial spread noise within minutes of entry

**Fix:** Add `direction = position.get("direction", "")` near line 2004 (where `strategy` is extracted).

**Verification:** The WS exit callback (`ws_price_watcher.py:475`) correctly reads `pos.get("direction", "")` — confirming the field exists on position dicts.

### C2: Positions <4h From Resolve Are INVISIBLE to Main Cycle Exit Logic

| Field | Value |
|-------|-------|
| **File** | `market_discovery_internal/cycles.py:689-691` |
| **Severity** | CRITICAL |
| **Discovered** | 23 April 2026 audit |
| **Affects Live** | YES |

**Code:**
```python
# Lines 689-691
if not live_market:
    next_open_positions.append(position)
    continue  # ← Skips ALL exit evaluation
```

**Problem:** `live_market` comes from `market_by_token` (line 647), built from `discovery["parsed"]`. The parser's golden window filter (`parsing.py:319`) rejects markets <4h from resolve. This means positions approaching resolution are NOT in `market_by_token`, so `live_market` is `None`, and the position **skips all exit evaluation**.

**Impact:**
- Late-window detection (2h before resolve): **NEVER TRIGGERS** via main cycle
- Thesis decay exit (confidence < 0.35): **NEVER TRIGGERS**
- Hold-to-resolve decision: **NEVER TRIGGERS**
- Forecast validation: **NEVER TRIGGERS**
- The position just sits there until WS triggers TP/SL or it expires
- `hours_until_resolve is None` warnings in logs are a symptom of this — the position is skipped before `hours_until_resolve` is even read

**Fix:** When `live_market` is None, compute `hours_until_resolve` from `position.get("end_date")` and fetch CLOB quote directly. Continue with exit evaluation using these values.

### C3: `monitor_pending_orders` Closes Position Without Checking Taker Sell Result

| Field | Value |
|-------|-------|
| **File** | `market_discovery_internal/cycles.py:1781-1790` |
| **Severity** | CRITICAL |
| **Discovered** | 23 April 2026 audit |
| **Affects Live** | YES (live mode only) |

**Code:**
```python
# Lines 1777-1790
taker_result = exchange.place_taker_sell(...)
fill_price = float(book["best_bid"])
closed = close_paper_position_fn(position=pos, exit_price=fill_price, ...)
# ← taker_result is NEVER checked!
```

**Problem:** When max retries are exceeded for a pending maker sell, the code places a taker sell as fallback. But it closes the position in the state **regardless of whether the taker sell succeeded**. If the taker sell fails (rejected, insufficient liquidity, etc.), the bot thinks it sold but the shares are still held on-chain.

**Impact (live mode):** Phantom close — bot's state says position is closed, but shares are still on-chain. Cash is credited for a sale that never happened. Orphaned shares with no tracking.

**Fix:** Check `taker_result.get("success")` before closing. If failed, revert position to `open` status.

## HIGH Bugs (5) — Should Fix Before Live Trading

### H1: Heartbeat Health Not Checked Before Order Placement

| Field | Value |
|-------|-------|
| **File** | `market_discovery_internal/execution.py` (all `place_*` methods) |
| **Severity** | HIGH |
| **Affects Live** | YES |

**Problem:** The `heartbeat_healthy` flag is set to `False` after 3 consecutive heartbeat failures, but none of the order placement methods check this flag. Orders can be placed when the heartbeat is dead, which means Polymarket may auto-cancel all open orders.

**Fix:** Add `if not self.heartbeat_healthy: return {"success": False, "reason": "heartbeat_dead"}` at the top of each `place_*` method.

### H2: Trailing Stop Requires `price <= entry_price` — Effectively Dead Code

| Field | Value |
|-------|-------|
| **File** | `market_discovery_internal/cycles.py:2028` |
| **Severity** | HIGH |
| **Affects Live** | YES |

**Problem:** The trailing stop condition requires `price <= entry_price` in addition to the 15% retrace from peak. This means the trailing stop only fires when price drops ALL the way back to entry — at which point the regular stop loss already handles it. The trailing stop provides zero additional protection.

**Example:** Buy at $0.10, price peaks at $0.15 (+50%), retraces to $0.1275 (15% from peak). Trailing stop does NOT fire because $0.1275 > $0.10 entry. Price must drop to $0.10 for trailing stop, but regular SL at $0.048 fires first.

**Fix:** Remove the `price <= entry_price` condition, or redesign to use a percentage-based trailing stop from peak.

### H3: Weather Evidence Source String Mismatch — Quality Systematically Underrated

| Field | Value |
|-------|-------|
| **File** | `market_discovery_internal/analysis.py:61-66` |
| **Severity** | HIGH |
| **Affects Live** | YES |

**Problem:** The quality score source component only recognizes `"dual-source"` (0.95) and `"open-meteo"` (0.85). But actual sources from `fetch_forecast` include `"verified-triple-source"`, `"verified-dual-source"`, `"verified-dual-source (METAR)"`, `"open-meteo (bulk)"`, etc. None match exactly, so they all get default 0.70.

**Impact:** A verified triple-source forecast (best quality) gets 0.70 instead of 0.95. This makes `is_weather_evidence_valid` more likely to reject good evidence, potentially causing false thesis-broken exits via `forecast_still_valid`.

**Fix:** Update the source matching to use substring/regex matching: `if "dual" in source or "triple" in source: score = 0.95`.

### H4: `monitor_pending_orders` Closures Not in `closed_this_cycle`

| Field | Value |
|-------|-------|
| **File** | `market_discovery_internal/cycles.py:1694-1710` |
| **Severity** | HIGH |
| **Affects Live** | YES |

**Problem:** When `monitor_pending_orders` closes a pending_exit position (order filled), it appends to `state["history"]` and updates cash, but doesn't add to `closed_this_cycle`. This means no Telegram notification is sent and cycle metrics undercount closures.

**Fix:** Return closed positions from `monitor_pending_orders` and add them to `closed_this_cycle` in the main cycle.

### H5: Live Exit Uses Original `position` Instead of `updated_position`

| Field | Value |
|-------|-------|
| **File** | `market_discovery_internal/cycles.py:860-862` |
| **Severity** | HIGH |
| **Affects Live** | LOW (cosmetic — PnL is correct) |

## Root Cause Analysis: Why All 3 Trades on 23 April Lost

### Direct Cause: Bug C1 (SL Cooldown Never Works)

All 3 positions (Lucknow, Milan, Seattle) were stopped out within minutes of entry. The 2-hour stop-loss cooldown was supposed to protect against initial spread noise, but `NameError` on `direction` variable silently disabled it.

### Contributing Factors:
1. **Bug F1 (now fixed):** CLOB key mismatch meant position evaluation used stale Gamma data, potentially showing lower prices than reality
2. **Bug C2:** Positions approaching resolve were invisible to main cycle, preventing thesis-based exits that could have been more favorable than stop loss
3. **Bug H3:** Weather evidence quality underrated, potentially causing premature thesis-broken exits (Seattle's `sniper_stop_loss_thesis_broken`)

### Timeline:
```
06:02 UTC  Lucknow opened at $0.13
06:46 UTC  Seattle opened at $0.09
06:51 UTC  Seattle closed — sniper_stop_loss_thesis_broken @ $0.08 (PnL: -$0.16)
06:53 UTC  Milan closed — stop_loss @ $0.05 (PnL: -$0.54)
07:47 UTC  Lucknow closed — stop_loss @ $0.06 (PnL: -$0.58)
           Total loss: -$1.29 (25.8% of $5.00 wallet)
```

Without Bug C1, the 2-hour cooldown would have prevented Milan and Lucknow stop losses from firing. The prices may have recovered (or not), but the bot would have had time to evaluate properly.

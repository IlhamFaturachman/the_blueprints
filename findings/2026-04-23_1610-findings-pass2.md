## Verification of Previously-Applied Fixes (F1-F5)

### F1: CLOB Key Mismatch Fix — VERIFIED CORRECT

**File:** `cycles.py:694-697`

The `or` chain `(quote or {}).get("bid") or (quote or {}).get("best_bid")` has a theoretical falsy-zero edge case: if `bid` is literally `0.0`, Python treats it as falsy and falls through. However, a $0.00 bid means "no bids exist" and is already filtered by `PENNY_BID_THRESHOLD` at line 718. The accidental fallthrough produces the correct behavior.

**Verdict:** CORRECT. No action needed.

### F2: Dashboard Regex Fix — VERIFIED CORRECT (with cosmetic gaps)

All 15 possible `close_reason` strings were traced. 10 match a styled regex. 5 fall through to the default handler:

| Unmatched Reason | Displayed As | Severity |
|-----------------|-------------|----------|
| `late_window_forecast_invalid` | "LATE WINDOW FORECAST INVALID" (yellow) | Low |
| `late_window_confidence_below_min` | "LATE WINDOW CONFIDENCE BELOW MIN" (yellow) | Low |

The default handler shows the raw string uppercased with underscores as spaces — readable but unstyled. Not a bug, just cosmetic.

**Verdict:** CORRECT. Cosmetic improvement possible but not blocking.

### F3: fetchData WS Price Preserve — VERIFIED CORRECT

- **First load:** `latestPositions` is `[]` → `_wsPrices` is empty → all positions use `serverPrice`. Correct.
- **Page reload:** All JS state destroyed → fresh start. No stale persistence. Correct.
- **WS disconnect:** WS prices persist in memory within a session. If WS drops for 10 minutes, the last WS price continues to override server price. This is a minor display issue (LOW severity) — the stale WS price is at most a few minutes old from the last WS update, and the server price is at most 5 minutes old from the last cycle. Neither is "fresh" in this scenario.

**Verdict:** CORRECT. Minor display edge case on WS disconnect (LOW).

### F4: WS Unsubscribe — VERIFIED CORRECT

Payload `{"operation": "unsubscribe", "assets_ids": [...]}` matches Polymarket official docs exactly. No `custom_feature_enabled` needed for unsubscribe (docs show it's only for subscribe).

**Verdict:** CORRECT.

### F5: Zombie Guard — VERIFIED CORRECT

- **Timezone format mismatch:** Uses raw string comparison on `opened_at`. If formats differ between memory and DB round-trip, the guard fails conservatively (keeps the position). Self-healing on next cycle. LOW severity.
- **Modified-but-not-closed positions:** Correctly handled — `pending_exit` is included in `_fresh_token_keys` filter.
- **New positions opened during cycle:** Correctly preserved — `not in _original_token_keys` check keeps them.

**Verdict:** CORRECT. Minor timezone format edge case (LOW, self-healing).

## New Findings

### AREA 1: Config Consistency

#### S1: Flash Crash L1 Threshold May Be Too Permissive
- **File:** `config.py:531` — `FLASH_CRASH_MAX_DROP_PCT = 0.40`
- **Severity:** MEDIUM
- **Impact:** A 40% single-tick drop is allowed before spike detector fires. For a $0.10 token, a drop to $0.06 is "normal." Moderate crashes (20-39%) bypass L1 entirely, allowing stop-loss to fire on what might be a flash crash.
- **Affects Live:** Yes — could cause premature stop-loss on flash crashes.

#### S2: `PENNY_BID_THRESHOLD` Hardcoded in Broadcaster
- **File:** `market_discovery.py:433` — `price > 0.01` hardcoded instead of using `PENNY_BID_THRESHOLD`
- **Severity:** LOW
- **Impact:** If threshold is changed via env var, broadcaster filter won't update. Display-only.

### AREA 2: Telegram Alerting

#### S3: Telegram Dedup Cache Poisoned on Failed Send
- **File:** `utils.py:99` vs `utils.py:122`
- **Severity:** MEDIUM
- **Impact:** The dedup key is recorded BEFORE the HTTP send. If the send fails, the message is still marked as "sent" in the dedup cache, suppressing retries for 5 minutes. Critical alerts (circuit breaker trigger, stop loss) could be silently lost.
- **Affects Live:** Yes — missed critical alerts.
- **Fix:** Move dedup recording to AFTER successful send.

#### S4: Telegram Sends Block Main Cycle
- **File:** `utils.py:122` — `requests.post` with 5-10s timeout
- **Severity:** MEDIUM
- **Impact:** Each Telegram send blocks the calling thread. A cycle with 5 closures + 3 entries = 8 sends × 10s timeout = up to 80 seconds blocked. Delays time-sensitive exits.
- **Affects Live:** Yes — cycle latency.
- **Fix:** Move Telegram sends to a background thread/queue.

---

### AREA 3: Command Server + Kill Switch

#### S5: CORS Policy Allows Any Origin with `:8080`
- **File:** `command_server.py:142`
- **Severity:** MEDIUM
- **Impact:** `":8080" in origin` matches `https://evil.com:8080`. Cross-origin requests from malicious sites could read state data or trigger kill switch (if they have the token).
- **Affects Live:** Yes — information disclosure risk.
- **Fix:** Use exact origin match only.

#### S6: Kill Switch Token Accepted via URL Query Parameter
- **File:** `command_server.py:42-43`
- **Severity:** MEDIUM
- **Impact:** Query parameters are logged in web server access logs, browser history, and proxy logs. Token leakage.
- **Affects Live:** Yes — security risk.
- **Fix:** Accept token only via header (`X-Kill-Token`), not query parameter.

#### S7: `/api/state` Exposes Trading Strategy Without Auth
- **File:** `command_server.py:89-106`
- **Severity:** MEDIUM
- **Impact:** Full portfolio state including `stop_loss_price`, `target_price`, `entry_price` for all positions. If VPS is misconfigured, an attacker could front-run the bot.
- **Affects Live:** Yes — information disclosure.
- **Fix:** Add basic auth or IP whitelist for `/api/state`.

### AREA 4: Data Warmer

#### S8: Warmer Stores Unvalidated Forecast Data
- **File:** `warmer.py:69-79`
- **Severity:** MEDIUM
- **Impact:** If Open-Meteo returns garbage data (null, extreme values), it gets cached and used by the main cycle. The anomaly detection (±7°C) catches extreme outliers but moderate errors (±3-5°C) pass through.
- **Affects Live:** Yes — wrong probability calculations.
- **Fix:** Add temperature range validation (e.g., -60°C to +60°C) before caching.
